# ADR-0004: Политика паролей и хеширование администратора

**Статус:** Принято (Этап 6).
**Вопрос реестра:** Q10 (политика паролей), Q11 (хеширование).
**Источник:** `docs/architecture/ecobilling-architecture.md`, раздел 21.4.

## Контекст

Пароль системного администратора нужно как-то хранить и проверять на минимальную устойчивость, без
изобретения собственной криптографии и без лишних зависимостей для небольшого числа администраторов.

## Решение

- **Q11, хеширование:** PBKDF2 через встроенный `PasswordHasher<TUser>` ASP.NET Core Identity, не Argon2id —
  без новых зависимостей; современные параметры итераций PBKDF2 соответствуют текущим рекомендациям NIST
  для системы с небольшим числом администраторов.
- **Q10, политика паролей:** базовый уровень NIST SP 800-63B — минимум 12 символов, без принудительной
  сложности, без принудительной периодической смены. Проверка по списку утечек (например HaveIBeenPwned)
  сознательно **не реализована** на этом этапе — внешняя сетевая зависимость, отложена как будущее
  улучшение, не открытый вопрос.

## Последствия

- Пароли директора/контроллера/жителя — отдельный вопрос округа EcoBilling, не затронутый этим решением.
- Отсутствие проверки по списку утечек — принятый компромисс, а не пробел: явно отложено, с известной
  причиной (внешняя зависимость).
