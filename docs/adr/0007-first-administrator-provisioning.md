# ADR-0007: Создание первого системного администратора

**Статус:** Принято (Этап 6).
**Вопрос реестра:** Q4.
**Источник:** `docs/architecture/ecobilling-architecture.md`, раздел 21.4.

## Контекст

Кто-то должен создать самого первого системного администратора — до этого момента нет ни одного
аутентифицированного пользователя, который мог бы вызвать защищённый HTTP endpoint для этого. Нужен способ,
не создающий публичную дверь в систему.

## Решение

Отдельная консольная команда provisioning (`EcoBilling.Control.Provisioning`), а не seed при старте
веб-процесса на основе секрета из окружения. Это **единственный** способ создать администратора вообще —
нет ни публичной регистрации, ни HTTP endpoint для этого. Пароль запрашивается интерактивно с
маскированным вводом, никогда не передаётся как аргумент командной строки (аргументы командной строки
видны в истории процессов/логах).

## Последствия

- Создание нового администратора требует прямого доступа к окружению развёртывания (запуска CLI), а не
  сетевого вызова — сознательно повышенный порог для операции, которая случается редко и имеет высокий
  уровень доверия.
- Успех и отказ этой команды всё равно аудируются (`AdministratorId = null`, так как нет вызывающего
  HTTP-администратора) — тот же журнал, что и у HTTP-инициированных административных действий.

## Найденный и исправленный дефект (Этап 18)

Аудирование (выше) требует `IAuditWriter`, но `Provisioning/Program.cs` не регистрировал его в своём
`ServiceCollection` — CLI падал с `InvalidOperationException` при любом реальном запуске. Обнаружено живым
запуском команды из README, не по коду; ни один юнит-тест это не покрывал, так как тесты обработчика
конструируют `IAuditWriter` вручную, минуя реальную композицию CLI. Исправлено (регистрация
`IHttpContextAccessor`/`IAuditWriter`) и закрыто регрессионным тестом `ProvisioningCliTests`, который
запускает настоящий скомпилированный `.dll` отдельным процессом против реального PostgreSQL — см. раздел
22.5 архитектурного документа, версия 0.12.
