# ADR-0001: Формат и нормализация кода округа

**Статус:** Принято, частично (раздел 26 «Код округа»: один под-вопрос остаётся открытым).
**Источник:** `docs/architecture/ecobilling-architecture.md`, раздел 17.3.

## Контекст

Код округа — публичный маршрутизирующий идентификатор (`BISHKEK-01`), а не пароль или токен: он человекочитаем
и, следовательно, угадываем по конструкции. Нужно было зафиксировать его формат, правило нормализации и то,
чем защищается endpoint `ResolveDistrict` от перебора.

## Решение

- Формат: 2-10 заглавных латинских букв, дефис, 2-4 цифры — `^[A-Z]{2,10}-[0-9]{2,4}$`, проверяется после
  нормализации.
- Нормализация: `Trim()` + приведение к верхнему регистру **только** инвариантной культурой (культурно-зависимый
  `ToUpper()` под тюркскими локалями ломает уникальный индекс: `i` → `İ`).
- Класс цифр — `[0-9]`, не `\d`: `\d` в .NET также соответствует не-ASCII десятичным цифрам.
- Нормализация не удаляет разделители, не выполняет NFKC, не меняет дефис.
- Единственная защита от перебора — rate limiting на публичном endpoint (см. [ADR-0005](0005-administrator-login-lockout-and-rate-limiting.md)), не непрозрачность формата: код округа — маршрутизатор, не секрет.

## Последствия

- `NormalizedCode` несёт уникальный индекс; `Code` хранит исходное написание только для отображения.
- Нормализация обязана совпадать при создании округа и при resolve — иначе уникальный индекс и запрос
  разойдутся.

## Открытый вопрос

**Можно ли менять код после активации округа — не решено.** До явного решения код считается неизменяемым
после создания.
