# ADR-0002: Сервисная аутентификация Control → EcoBilling

**Статус:** Принято (Этап 8).
**Источник:** `docs/architecture/ecobilling-architecture.md`, раздел 20.4.

## Контекст

`DistrictClient` вызывает защищённый внутренний API округа (`CreateDirector`/`ResetDirectorPassword`).
Нужен способ доказать округу, что вызов действительно исходит от Control, без общего секрета, который
скомпрометировал бы весь реестр округов сразу при утечке у одного округа.

## Решение

- Асимметричная подпись **ES256** (ECDSA, кривая P-256, SHA-256), не общий секрет: EcoBilling проверяет
  подпись открытым ключом Control и никогда не получает ничего, что само по себе позволило бы подделать
  токен.
- Подписанный service-assertion JWT: короткоживущий, с ротацией и отзывом ключа.
- Распространение открытого ключа между Control и округами **пока ручное, не через JWKS-эндпоинт**
  (`/.well-known/jwks.json`) — это осознанно отложенное решение, а не открытый вопрос: явно принятая
  временная стоимость на время перехода.

## Последствия

- Компрометация ключа одного округа не даёт доступа к другим округам (в отличие от общего секрета).
- Ручное распространение ключа — операционная нагрузка при ротации; переход на JWKS остаётся будущим
  улучшением, не блокирующим текущую эксплуатацию.
