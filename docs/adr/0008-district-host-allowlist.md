# ADR-0008: Список разрешённых хостов округа

**Статус:** Принято (Этап 5).
**Вопрос реестра:** Q18.
**Источник:** `docs/architecture/ecobilling-architecture.md`, раздел 21.2.

## Контекст

`TrustedApiUrl` (Этап 1) уже структурно проверяет `ApiBaseUrl` округа (HTTPS, без userinfo, без
query/fragment, без loopback/private/link-local/metadata-адресов), но модель развёртывания округов (единый
домен под управлением Control или размещение округом самостоятельно) ещё не определена. Нужна вторая,
независимая линия защиты на время, пока это не решено.

## Решение

`CreateDistrict` и `UpdateDistrict` дополнительно проверяют хост нового `ApiBaseUrl` по явному списку в
конфигурации (`Districts:AllowedHosts`). Оба уровня защиты действуют одновременно, второй не заменяет
первый.

- Формат — явный список точных хостов, а не маска домена: более безопасный выбор на время, пока модель
  развёртывания не определена.
- Поле названо `AllowedHosts`, не `AllowedExactHosts` — формат спроектирован как *append-only*, чтобы
  возможное будущее ослабление до маски доменов (`AllowedHostSuffixes`) можно было добавить отдельным
  полем, не переименовывая существующее.
- Пустой или отсутствующий список означает «ничего не разрешено», не «проверка отключена».
- Проверка применяется только к новому/изменяемому адресу от администратора, не при каждом чтении округа
  из базы — иначе сокращение списка задним числом сломало бы уже существующие округа.

## Последствия

- Компрометация или ошибочная конфигурация одного округа не расширяет допустимые адреса для всех: список
  централизован в конфигурации Control, а не в данных округа.
